A CLEARER VIEW OF YOUR CODE

Evidence, before you ship.

01 / Bring the current source and diff

Upload the project folder AFTER your edits and a unified diff from the same repository root. The analyzer validates patch context and reconstructs the previous source.

02 / Trace both versions

A Python syntax parser identifies functions, imports and direct calls. We combine the previous and current dependency graphs, including removed functions, and walk backwards from changes to callers and tests.

03 / Inspect the evidence

Every recommended test has an explanation path. Module-level changes trigger broader analysis. Unresolved calls and syntax recovery are reported in Diagnostics.

Static analysis cannot prove that unselected tests are safe to skip. Python fixtures, decorators, inheritance, runtime imports and dynamic dispatch can hide dependencies. Run the complete suite before release.

Supported scope

Python source; explicit imports and aliases; direct function calls; same-class self/cls calls; nested functions; standard pytest-style test functions and methods. No code is executed and no remote repository is fetched.

Privacy & limits

No project source is written to a database, log or browser storage by this application. Requests are processed by the hosting provider. Maximum: 80 .py files, 600 KB source, 1,200 functions. Exported reports may include code; keep them private when needed.
